# 🌌 Django-проект Torch (Backend API)

**Torch** — это комплексная backend-платформа для LMS-системы онлайн-обучения (Learning Management System). Проект предоставляет гибкий REST API, построенный на базе Django REST Framework, со строгим разделением зон ответственности, фоновым планированием задач и архитектурным паттерном **Service Layer** для интеграции со сторонними платежными шлюзами и автоматизации бизнес-логики.

---

## 🏗 Архитектура и структура модулей

Проект разделен на два ключевых доменных приложения:

### 1. `users`
* **Аутентификация:** Регистрация, разграничение прав доступа и безопасность сессий с помощью JWT-токенов (`Simple JWT`).
* **Жизненный цикл аккаунтов:** Сервисный слой `UserActivityService` отслеживает дату последнего входа пользователей.
* **Автоматическая блокировка:** Интегрирована фоновая очистка базы данных от неактивных пользователей, не посещавших платформу более 30 дней.

### 2. `aurora`
* **Контент:** Управление каталогом онлайн-обучения — курсы (`Course`) и отдельные уроки (`Lesson`), связанные отношением One-to-Many. Реализовано «мягкое удаление» (Soft Delete) через флаг архивации для сохранения целостности аналитических данных.
* **Финансы:** Учет транзакций через модель `Payments` (поддерживает наличные, переводы на счет и интернет-эквайринг).
* **Интеграция со Stripe:** Модуль автоматической генерации платежных ссылок через инструмент Stripe Checkout и асинхронный прием уведомлений (Webhooks). Вся логика API Stripe вынесена из контроллеров в изолированный сервисный слой `StripePaymentService` (`services.py`).
* **Уведомления:** Сервисный слой `process_course_updates_cron` автоматически группирует изменения контента и рассылает email-уведомления подписчикам с задержкой в 4 часа для защиты от спама.

## 🛠 Технологический стек

* **Язык программирования:** Python 3.x
* **Веб-фреймворк:** Django + Django REST Framework (DRF)
* **Платежный шлюз:** Stripe API (Интеграция через современный SDK `StripeClient`)
* **База данных:** PostgreSQL
* **Брокер сообщений & Кэш:** Redis (Разворачивается локально через Docker-контейнер)
* **Асинхронные задачи:** Celery
* **Планировщик задач:** Celery Beat (Автоматизация регулярных проверок базы данных)

---

## ⏰ Фоновые и периодические задачи (Celery Beat)

В проекте настроен планировщик `CELERY_BEAT_SCHEDULE`, который изолирует регулярные тяжелые операции от основного потока обработки API:

1. **Рассылка обновлений курсов (`aurora`):** Запускается каждые 30 минут. Проверяет курсы, контент которых (или входящие уроки) изменился более 4 часов назад, и ставит задачи веерной отправки писем в специализированную очередь `emails`.
2. **Блокировка неактивных пользователей (`users`):** Запускается ежедневно в `02:00` ночи. Автоматически переводит флаг `is_active` в состояние `False` для всех учетных записей, у которых поле `last_login` устарело более чем на 30 дней (исключая администраторов и персонал).

## 🔧 Тестирование интеграций

### Как протестировать платежи (Stripe)
1. Установите [Stripe CLI](https://github.com).
2. Выполните команду `stripe login` для авторизации.
3. Запустите вебхуки: `stripe listen --forward-to localhost:8000/api/v1/payments/webhook/`
4. Скопируйте полученный `whsec_...` в ваш файл `.env` в переменную `STRIPE_WEBHOOK_SECRET`.
5. Запустите Django-сервер и сделайте тестовый платеж.

### Как протестировать Celery Beat локально
Периодические задачи используют брокер Redis. Убедитесь, что Docker Desktop запущен перед началом работы. Планировщик автоматически подхватит конфигурацию из настроек проекта.

## 🚀 Быстрый старт (Локальная разработка)

В проекте настроена автоматизация, которая одной командой поднимает всю необходимую инфраструктуру.

### Предварительные требования
1. Установлен и запущен **Docker Desktop** (необходим для автоматического поднятия Redis).
2. Активировано виртуальное окружение вашего проекта (Poetry / venv).

### Запуск проекта
Вместо стандартного `runserver` используйте кастомную команду автоматизации:
```bash
python manage.py dev
```

**Что делает эта команда автоматически:**
1. Проверяет наличие Docker в системе.
2. Скачивает образ и запускает изолированный контейнер `torch-redis` на порту `6379`.
3. Запускает локальный веб-сервер Django на `http://127.0.0.1:8000`.
4. Включает воркер Celery в режиме совместимости с Windows (`-P threads`), а также запускает демон планировщика Celery Beat для симуляции периодических задач.

При нажатии `Ctrl + C` в терминале скрипт корректно завершит процессы Django и Celery, а также остановит контейнер Redis, освобождая оперативную память вашего ПК.
